## 2. 技术选型与理由

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3.5 + `<script setup>` + TypeScript | JD 首选；组合式 API 利于抽状态逻辑 |
| 构建 | Vite 7 | 冷启动快，评审 `npm run dev` 秒开 |
| 样式 | Tailwind CSS + CSS 变量 | 设计 token 可统一管理；直接命中 JD 加分项 |
| 组件 | shadcn-vue（Radix Vue 底座） | 无默认皮肤，样式完全可控；自带可访问性 |
| 服务端状态 | TanStack Query (Vue) | 缓存、重试、失效、乐观更新开箱即用，避免手写 loading/error |
| 客户端状态 | Pinia | 仅存 UI 状态（筛选、选中项、抽屉开关） |
| 图表 | ECharts（按需引入） | 趋势图、环形图、分布图；体积可控 |
| 后端 | Spring Boot 3.5 + Java 21 | JD 核心要求 |
| ORM | MyBatis-Plus | JD 明确提到 MyBatis；分页插件省事 |
| 数据库 | H2（默认）/ MySQL 8（可选） | 零配置可跑 vs 贴近生产，二者兼得 |
| 实时 | Spring WebSocket（原生） | 比 STOMP 轻，前端一行 `new WebSocket()` 即可 |
| 文档 | springdoc-openapi | 自动生成 OpenAPI，前端类型可对齐 |
| 测试 | Vitest + Spring Boot Test | 覆盖状态机与工具函数 |

**为什么不用 Element Plus**：默认视觉是「通用后台」风格，与本项目强调的 UI 审美目标冲突；改造其样式成本高于直接用无皮肤组件。

## 4. 接口设计

### 4.1 统一响应

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "a1b2c3" }
```

- HTTP 状态码语义正确（200/400/404/409/500）
- `code = 0` 表示业务成功；非 0 为业务错误码

**错误码**

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败（`data` 内含字段级错误） |
| 40401 | 404 | 任务不存在 |
| 40901 | 409 | 状态冲突（乐观锁 / 非法流转） |
| 50000 | 500 | 服务端异常 |

### 4.2 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/dashboard/summary` | 概览指标 |
| GET | `/api/v1/tasks` | 分页查询（status/keyword/scriptId/dateRange/page/size/sort） |
| GET | `/api/v1/tasks/{id}` | 详情 |
| POST | `/api/v1/tasks` | 创建 |
| PATCH | `/api/v1/tasks/{id}/status` | 状态流转 `{action, version}` |
| POST | `/api/v1/tasks/{id}/duplicate` | 复制 |
| DELETE | `/api/v1/tasks/{id}` | 删除（仅草稿） |
| GET | `/api/v1/tasks/{id}/results` | 通话结果分页 |
| GET | `/api/v1/meta/scripts` | 话术模板 |
| GET | `/api/v1/meta/lines` | 线路及并发占用 |
| GET | `/api/v1/tasks/stats` | 各状态计数（供 Tab） |
| WS | `/ws/tasks` | 进度推送 |

### 4.3 分页约定

请求 `page`（从 1 开始）、`size`（默认 10，上限 100）；响应：

```json
{ "items": [], "page": 1, "size": 10, "total": 24, "totalPages": 3 }
```

### 4.4 状态流转接口

```http
PATCH /api/v1/tasks/T20261103001/status
{ "action": "PAUSE", "version": 3 }
```

`action ∈ START | PAUSE | RESUME | TERMINATE | CANCEL`
服务端由 `TaskStateMachine` 统一校验，非法流转返回 `40901`。

### 4.5 WebSocket 消息

```json
{ "type": "task.progress", "taskId": "T20261103001", "payload": { "calledCount": 1240, "connectedCount": 512, "status": "RUNNING" } }
```

- 连接后客户端发送 `{"type":"subscribe","taskIds":["..."]}`
- 断线指数退避重连（1s → 2s → 4s，上限 30s）
- 页面不可见（`document.hidden`）时暂停渲染，避免无谓刷新

## 5. 数据库设计

```sql
CREATE TABLE task (
  id                 VARCHAR(32) PRIMARY KEY,
  name               VARCHAR(64)  NOT NULL,
  script_id          VARCHAR(32)  NOT NULL,
  line_id            VARCHAR(32)  NOT NULL,
  status             VARCHAR(16)  NOT NULL,
  priority           VARCHAR(8)   NOT NULL DEFAULT 'NORMAL',
  total_contacts     INT          NOT NULL DEFAULT 0,
  called_count       INT          NOT NULL DEFAULT 0,
  connected_count    INT          NOT NULL DEFAULT 0,
  intent_count       INT          NOT NULL DEFAULT 0,
  total_duration_sec INT          NOT NULL DEFAULT 0,
  concurrency        TINYINT      NOT NULL DEFAULT 10,
  retry_limit        TINYINT      NOT NULL DEFAULT 1,
  retry_interval_min INT          NOT NULL DEFAULT 30,
  call_window        VARCHAR(16)  NOT NULL DEFAULT '09:00-20:00',
  scheduled_at       TIMESTAMP    NULL,
  started_at         TIMESTAMP    NULL,
  finished_at        TIMESTAMP    NULL,
  creator_name       VARCHAR(32)  NOT NULL,
  created_at         TIMESTAMP    NOT NULL,
  updated_at         TIMESTAMP    NOT NULL,
  version            INT          NOT NULL DEFAULT 0
);
CREATE INDEX idx_task_status_created ON task(status, created_at DESC);
CREATE INDEX idx_task_name ON task(name);

CREATE TABLE script (
  id VARCHAR(32) PRIMARY KEY, name VARCHAR(64), industry VARCHAR(32),
  version VARCHAR(16), status VARCHAR(16)
);

CREATE TABLE line (
  id VARCHAR(32) PRIMARY KEY, name VARCHAR(64), provider VARCHAR(32),
  capacity INT, used INT, status VARCHAR(16)
);

CREATE TABLE call_result (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, task_id VARCHAR(32) NOT NULL,
  phone VARCHAR(32), result VARCHAR(16), duration_sec INT,
  hangup_cause VARCHAR(32), intent_level VARCHAR(4), called_at TIMESTAMP
);
CREATE INDEX idx_result_task ON call_result(task_id, called_at DESC);

CREATE TABLE task_event (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, task_id VARCHAR(32) NOT NULL,
  type VARCHAR(32), message VARCHAR(255), created_at TIMESTAMP
);
```

**说明**

- `version` 用于乐观锁，`UPDATE ... WHERE version = ?`，影响行数为 0 则抛 `40901`
- 索引覆盖高频查询：状态 + 创建时间倒序
- 通话明细与任务分表，避免单表过宽

## 6. 关键实现点

### 6.1 双模式 API 适配层

```ts
// api/client.ts
const mode = import.meta.env.VITE_API_MODE ?? 'http'

export const request = mode === 'mock' ? mockRequest : httpRequest
```

- `http`：真实后端，`fetch` + 超时 + AbortController
- `mock`：MSW 拦截，返回与后端**完全同构**的数据
- 两种模式共用同一套 `types.ts`，避免"mock 一套、真实一套"

**收益**：前端可独立部署到 Vercel 作为在线预览，后端在本地真实联调，互不阻塞。

### 6.2 状态演示开关（评审友好）

`VITE_API_MODE=mock` 时，右下角出现「演示」浮层，可一键切换：

`正常 / 加载中 / 空数据 / 请求失败 / 无权限 / 慢网络`

实现方式：mock handler 读取 `?__scenario=`，返回对应响应。
**目的**：评审需要验证"状态完整性"，让他 5 秒内看完所有状态，而不是靠翻代码想象。

### 6.3 筛选与 URL 同步

```
/tasks?status=running&q=618&page=2
```

- 单向数据流：URL 是唯一真源，UI 从 URL 派生
- 切换筛选时重置 `page=1`（避免越界空页）
- 使用 `router.replace` 避免污染浏览器历史

### 6.4 乐观更新

```ts
onMutate: async ({ id, action }) => {
  await queryClient.cancelQueries(['tasks'])
  const prev = queryClient.getQueryData(['tasks'])
  queryClient.setQueryData(['tasks'], optimisticPatch(prev, id, action))
  return { prev }
},
onError: (_e, _v, ctx) => queryClient.setQueryData(['tasks'], ctx.prev)
```

暂停/恢复先改 UI，失败回滚 + Toast。**这是"状态完整性"里最容易被忽略、也最能体现工程成熟度的一点。**

### 6.5 状态机（后端唯一权威）

```java
public enum TaskStatus { DRAFT, SCHEDULED, RUNNING, PAUSED, COMPLETED, FAILED, TERMINATED, CANCELLED }

private static final Map<TaskStatus, Map<TaskAction, TaskStatus>> TRANSITIONS = Map.of(
  DRAFT,     Map.of(SUBMIT, SCHEDULED, DELETE, CANCELLED),
  SCHEDULED, Map.of(START, RUNNING, CANCEL, CANCELLED),
  RUNNING,   Map.of(PAUSE, PAUSED, TERMINATE, TERMINATED, COMPLETE, COMPLETED, FAIL, FAILED),
  PAUSED,    Map.of(RESUME, RUNNING, TERMINATE, TERMINATED)
);
```

前端也维护一份**只读副本**用于按钮禁用，但**以服务端校验为准**——避免"前端能点、后端报错"的割裂。

### 6.6 定时任务模拟外呼

```java
@Scheduled(fixedRate = 2000)
public void tick() {
  // 取 RUNNING 任务，按并发数推进 calledCount，随机生成通话结果
  // 推送 WebSocket，写 call_result
}
```

既让进度"活"起来，也顺带命中 JD 加分项「定时任务 / 任务调度」。

### 6.7 前端类型对齐

由 springdoc 生成 OpenAPI，`openapi-typescript` 产出 `types.ts`：

```
mvn spring-boot:run  →  http://localhost:8080/v3/api-docs
npm run gen:types    →  src/api/types.ts
```

保证前后端契约不漂移；也向评审展示"接口先行"的习惯。

### 7.1 设计 token

| 类别 | Token | 值 |
|---|---|---|
| 画布 | `--bg` | `#F6F5F1`（暖白，非冷灰） |
| 卡片 | `--surface` | `#FFFFFF` |
| 描边 | `--border` | `#E4E1DA` |
| 主文字 | `--ink` | `#16191F` |
| 次文字 | `--ink-2` | `#5B6270` |
| 弱文字 | `--ink-3` | `#8B919E` |
| 主色 | `--accent` | `#0B6B5F`（深青，信号/连接语义） |
| 强调 | `--accent-2` | `#C2841A`（琥珀，用于警示与图表第二序列） |
| 成功 | `--ok` | `#2E7D5B` |
| 警示 | `--warn` | `#B7791F` |
| 危险 | `--danger` | `#B4472F` |
| 圆角 | `--r` | 10px（卡片 14px） |
| 阴影 | `--shadow` | `0 1px 2px rgba(22,25,31,.04), 0 8px 24px -12px rgba(22,25,31,.12)` |

### 7.2 字体

- UI：`"IBM Plex Sans", "PingFang SC", "Microsoft YaHei", sans-serif`
- 数字：`"IBM Plex Mono", ui-monospace`，`font-variant-numeric: tabular-nums`
- 字号阶梯：12 / 13 / 14 / 20 / 30，行高 1.5–1.2（标题收紧）

> 选 IBM Plex 而非 Inter：Plex 带有工程感与人文细节，适合技术型控制台；等宽数字能保证表格列对齐。

### 7.3 布局

- 侧栏 232px（可折叠至 64px），深墨色 `#12161C`，与暖白画布形成明确分区
- 内容最大宽 1440px，左右留白 32px
- 8px 栅格；卡片内边距 20px；区块间距 24px
- 表格行高 56px，表头 44px

### 7.4 动效

- 页面入场：卡片错峰上浮（`delay` 40ms 递增，总时长 ≤ 400ms）
- 数字变化：`countUp` 300ms
- 进度条：`width` 过渡 600ms `ease-out`
- 抽屉：220ms `cubic-bezier(.32,.72,0,1)`
- 遵循 `prefers-reduced-motion`，全部降级为无动画

## 8. 可运行性保障

评审的启动路径必须足够短：

```bash
# 方式一：前端（mock，无需后端）
cd web && npm i && npm run dev          # http://localhost:5173

# 方式二：全栈
cd server && mvn spring-boot:run        # http://localhost:8080
cd web && npm run dev                   # 自动代理 /api → 8080

# 方式三：Docker（可选）
docker compose up
```

**保障措施**

- H2 文件库，首次启动自动执行 `schema.sql` + `data.sql`，无需装任何数据库
- `data.sql` 预置 24 条任务，覆盖全部 6 种状态，含长名称、0 名单、异常任务等边界样本
- 提供 `npm run dev:mock` 与 `npm run dev:api` 两个脚本，避免环境变量记忆负担
- README 首屏即启动命令，不写废话

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Tailwind 与 shadcn-vue 版本兼容 | 构建失败 | 锁定已知兼容版本，先跑通最小页面 |
| WebSocket 在评审环境被拦截 | 实时进度不生效 | 降级为 3s 轮询，UI 无感知 |
| 评审机器无 Java 21 | 后端起不来 | README 注明；同时提供前端 mock 模式兜底 |
| 范围膨胀 | 交付质量下降 | 严格按第 8 节验收标准，超范围需求记入「后续规划」 |
| AI 生成代码风格不一致 | 可维护性差 | 统一 ESLint + Prettier + 组件模板，Review 清单兜底 |
