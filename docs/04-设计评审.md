## 1. 一句话总评与评分

**一句话总评：** 这是一份"审美明显高于平均线、业务语言也说得对，但演示动线被几个低级缺陷打断"的作品——配色、字体、信息密度已经像成熟 B 端产品，然而「演示浮层压住抽屉主按钮」「详情抽屉永远是第一条任务」「清除筛选是死按钮」会让评审在前 90 秒内失去信任；把这几处和对比度修掉，分数可以从 6.4 直接进到 8 分档。

### 1.1 评分

| 维度 | 分数 | 判断依据 |
|---|---|---|
| **UI 审美** | **7.5 / 10** | 暖白 `#F6F5F1` + 深青 `#0B6B5F` + IBM Plex 的组合有明确态度，避开了蓝灰后台模板；扣分在概览三卡宽度 5:3:4 造成层级倒挂、hero 卡数字与图表之间 44px 空洞、中文落进等宽字体、迷你趋势图沦为装饰 |
| **状态完整性** | **6.0 / 10** | 6 个演示场景 + 乐观更新回滚是加分项；但需求 §6 的 15 个场景只有 4 个完整落地（见 1.2），403 复用了 500 的壳，骨架屏只有 1 行且列位与表头错开 |
| **需求理解** | **7.5 / 10** | 「并发 46/80」「接通 / 已呼」「重呼 1 次 · 30 分钟」「行业均值 34.6%」「避免重复骚扰」这些措辞证明作者懂外呼业务，不是套 CRUD 模板；扣分在表格缺"意向/转化"、暂停无原因、文档承诺的 URL 同步 / 统计独立失败未落地，以及 §4.4 的 Step 4 确认（文档自身口径不一） |
| **可访问性** | **4.0 / 10** | 20+ 处文字对比度低于 4.5:1（最低 1.77:1），抽屉无焦点陷阱、关闭后 20 个控件仍在 Tab 序列，输入框焦点指示仅 1.41:1；按此状态 Lighthouse Accessibility 预计 65–75，达不到验收标准的 90 |
| **综合** | **6.4 / 10** | 加权：UI 30% + 状态 25% + 需求 25% + 可访问性 20% |

### 1.3 文档承诺 vs 实际实现（评审人会两边对照）

| 文档承诺 | 实际 |
|---|---|
| 8px 栅格；卡片内边距 20px；行高 56px；表头 44px（02 §7.3） | 实测 14 / 18 / 22 / 26 / 13 混用；行高 **58px**；表头 **40px** |
| 骨架屏高度与真实内容一致（01 §4.1） | 1 行 49px vs 10 行 × 58px |
| Tab 计数来自后端聚合（01 §4.2） | 硬编码，且与 12 条数据不符（见 P1-12） |
| 筛选条件同步 URL（01 §4.2） | 无 URL 同步 |
| 需求 §4.4 写「Step 4 确认」，但 §3 与用户故事写「3 步向导」——文档自相矛盾 | 实现取了 3 步，汇总塞进 Step 3；建议统一文档口径 |
| 意向等级 A/B/C/D（01 §4.5） | 只有 A/B/C |
| 遵循 prefers-reduced-motion（02 §7.4） | 无该媒体查询，脉冲/闪烁常驻 |
| 卡片错峰入场动画（02 §7.4） | 未实现 |

### 1.4 检索依据（skill 输出如何影响本报告）

- **ux**：`Focus States`（High）——"移除 outline 必须给替代"；`Empty States`——"文案 + 行动"；`Table Handling`——"横向滚动或卡片布局"；`Compact Control Semantics`——"用 button 并暴露 pressed/selected 状态"。
- **chart**：KPI 卡 + bullet/进度条适合并排 KPI；**颜色不能单独承载语义**，必须有文本兜底；少于 4 个数据点不要画趋势线（本页 7 点尚可，但缺轴/标签）。
- **color**：`Analytics Dashboard` 给出的 muted foreground 是 `#475569`（在 `#F8FAFC` 上约 7.5:1），而本稿的 `#8B919E` 只有 3.16:1——同一角色差了一个数量级。
- **typography**：`Dashboard Data`（Mono + Sans）与当前 IBM Plex 思路一致，方向正确；但要求正文 ≥12px、数字统一 tabular，本稿有 9.5/10.5px 的正文级文字。
- **design-system**：交叉验证给出的方案是"企业蓝 + 灰"，本稿的暖白 + 深青更有辨识度，**不建议换成蓝**；只需借用它的对比度纪律与 `prefers-reduced-motion` 检查项。

### 1.5 审美判断（frontend-design 视角）

| 维度 | 判断 | 说明 |
|---|---|---|
| **AI 生成感** | **低–中** | 加分：没有紫色渐变、玻璃拟态、emoji 图标、Inter/Roboto，暖白 + 深青 + Plex 是有意选择。扣分：结构仍是"3 KPI + 指标条 + Tab + 表格 + 抽屉"的标准后台骨架，记忆点主要来自表皮；声波只出现在 brand mark，没有延续成页面的图形母题（接通/未接通、并发水位都可以做成同一套视觉语言） |
| **信息层级** | **中** | 概览内部倒挂（P1-8）；表格内部反而清楚：名称 > ID、进度 > 计数、话术 > 版本，三组主次关系立得住 |
| **留白与节奏** | **中** | 间距是 14/18/22/26 的"2px 微差"，不是 8px 节拍；hero 44px 空洞、次指标 label 与 value 相距 262px，留白没有承担分组功能，只是"空着" |
| **字体** | **良** | Plex Sans + Mono 的方向正确、气质匹配；但中文落进 mono、15 级字号、9.5px 下限，让它"看起来精致、读起来费劲" |
| **动效** | **良** | 克制，没有弹跳和视差；抽屉 260ms、进度 600ms 的节奏舒服。缺 reduced-motion，且两个脉冲常驻，实时感的维护成本高于收益 |

**结论**：审美不是这份作品的问题，**"最后一公里的完成度"才是**——它已经越过了"像 AI 生成"的线，接下来要做的是把结构也做出产品辨识度（例如把"接通/未接通/并发"提炼成一套贯穿概览与表格的图形语言），而不是继续加渐变和阴影。

### 3.4 P0-4 筛选、分页、批量操作是装饰

**现象（实测）**

```js
  const kw = state.keyword.trim().toLowerCase();
  return TASKS.filter(t =>
    (state.tab === 'all' || t.status === state.tab) &&
    (!state.script || t.script === state.script) &&

$('#scriptFilter').addEventListener('change', e => {

function renderPager(total){
  const pages = Math.max(1, Math.ceil(total / state.size));
  $('.pager').innerHTML = `

    <button class="pg" data-page="${state.page-1}" ${state.page===1?'disabled':''} aria-label="上一页">…</button>

  $$('.pg[data-page]').forEach(b => b.onclick = () => {

```

### 3.9 P1-5 抽屉焦点陷阱与 Tab 序列

**实测**
- 打开详情后 `document.activeElement` 仍是行内「详情」按钮。
- 连按 6 次 Tab：`选择 → 详情 → BUTTON → 选择 → 详情 → 选择`，始终在背景表格。
- 关闭状态的两个抽屉共有 **20 个可聚焦控件**，`aria-hidden` 为 `null`，`visibility:visible`。

**为什么是问题**
键盘用户打开抽屉后无法进入内容；反过来，不打开抽屉时 Tab 会跑进屏幕外的抽屉，焦点"消失"。这是 WCAG 2.4.3 / 2.1.2 的典型失败。

**修复（`inert` 是最干净的方案）**

```js
const FOCUSABLE = 'a[href],button:not([disabled]),input:not([disabled]),select:not([disabled]),textarea:not([disabled]),[tabindex]:not([tabindex="-1"])';
let lastFocus = null;

function openDrawer(el){
  lastFocus = document.activeElement;
  el.removeAttribute('inert');
  el.classList.add('show');
  $('#scrim').classList.add('show');
  document.querySelector('.app').setAttribute('inert','');
  document.body.classList.add('drawer-open');
  (el.querySelector(FOCUSABLE) ?? el).focus();
}

function closeAll(){
  $$('.drawer').forEach(d => { d.classList.remove('show'); d.setAttribute('inert',''); });
  $('#scrim').classList.remove('show');
  document.querySelector('.app').removeAttribute('inert');
  document.body.classList.remove('drawer-open');
  lastFocus?.focus();
}

document.addEventListener('keydown', e => {
  if (e.key === 'Escape') return closeAll();
  if (e.key !== 'Tab') return;
  const el = document.querySelector('.drawer.show');
  if (!el) return;
  const f = [...el.querySelectorAll(FOCUSABLE)].filter(x => x.offsetParent !== null);
  const first = f[0], last = f[f.length - 1];
  if (e.shiftKey && document.activeElement === first){ e.preventDefault(); last.focus(); }
  else if (!e.shiftKey && document.activeElement === last){ e.preventDefault(); first.focus(); }
});
```

初始 HTML 给两个 `.drawer` 加 `inert`，`openDrawer` 时移除。这样关闭的抽屉自动退出 Tab 序列，不需要额外的 `aria-hidden` 维护。

## 5. 三条最高性价比的改进

### ① 先修 P0-1/2/3，再补 P0-4（约 80 行代码，收益最大）

- `body.drawer-open .demo{opacity:0;pointer-events:none}` → 解开向导和详情抽屉的按钮。
- `openDetail` 按行渲染 + 无数据兜底 → 详情不再"永远是 001"。

- 话术筛选 / 分页 / 批量操作接上状态（或删掉死控件）→ 工具栏不再是摆设。

前三处约 40 行、不涉及视觉返工，却直接决定评审能不能在 3 分钟内走完"看概览 → 筛执行中 → 开详情 → 建任务"的完整动线。**先做这个，再谈审美。**

### ② 一次性重做文字色板（6 个变量 + 3 条规则，可访问性从 4 提到 7）

把 `--ink-3` 提到 `#646C79`（5.30:1）、`--ink-4` 提到 `#676E7B`（5.13:1），三个状态标签换成 `#256B4C / #8A5A12 / #5B6270`，最小字号从 9.5/10.5 提到 12。视觉上几乎看不出变化，但 20+ 处"看不清的口径说明"全部达标，Lighthouse Accessibility 能从 ~70 拉到 90+，直接命中验收标准。

### ③ 表格列优先级 + 数字右对齐 + 操作列 sticky（一处改动，三个评分点同时得分）

- 数字列右对齐（名单量/接通率/意向），表头同步；
